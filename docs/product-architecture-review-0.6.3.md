# Xiaoxiao Agent 产品定位与架构评审

2026 年 11 月 25 日 · 基于本机 0.6.3 工作区。下文的发布门槛和客群选择是提案。

## 用户来这里完成什么

用户打开 Mac 上的 Xiaoxiao Agent，通过文字或声音提出目标，让自己选择的模型和工具完成工作。用户能看见进度，随时调整方向，拿到可以打开、修改、导出的成品。应用使用独立的名称、图标、配置与数据目录，可与 Claude 共存。

我建议先服务愿意自配模型 API、经常交付文档和创意素材的个人与小团队。开发工作台服务其中需要处理代码的用户。这个排序来自用户反复强调的文件、媒体、插话和首页体验，仍需与首批付费用户核对。如果首发面向研发团队，就把项目上下文、差异审阅和测试执行提前。如果近期就有组织采购，把数据策略、部署和审计提前到试点入口。定价与托管方式待验证。

**用一项任务验收。** 从丝结首页说「用这份活动资料，做一页给客户看的介绍，保存成 PDF」。中途发「日期改到周五，删掉预算」。用户看得见哪条要求已采用，能打开 PDF 检查内容，再从同一项目进入生图工作区做封面。重启后能找到原稿、封面和各自的版本。即使用户从未打开代码编辑器，整条路径也应成立。

## 0.6.3 对照

| 用户要求 | 现状与判断 | 怎样才算满足 |
|---|---|---|
| 独立品牌、共存、自选模型 | 独立应用标识和数据目录已具备。已有模型选择器和多种协议。切换服务商会发送当前有效会话历史。 | 首次用户能配通一个模型，从输入框直接切换。跨服务商时能看懂历史将发往哪里，只展示当前任务可用的模型。 |
| 首页到会话保持同一种美感 | 已有丝结、粒子和独立会话场景。用户认可首页，对进入对话后的视觉连续性给出过负面反馈。 | 点丝结后缩为会话状态标志，输入焦点连续。侧栏按需展开。监听、等待、执行、待审批各有文字和对应动效。动态图表展示实测数据，系统减少动态效果时保留全部操作和状态信息。 |
| 文件、插话、流式响应 | 已有流式输出、运行时补充、审批和恢复记录。补充会进入后续模型请求。在途请求有明确的生效边界。独立成品工具支持 HTML、SVG、CSS、JS、JSON、MD 和 TXT，Word/PDF 另走草稿导出。 | 用户说「做成 PDF」就走合适的路径。聊天区区分「收到补充」「正在按新要求执行」「已保存」「已验证」。能从交付卡打开文件并核对业务内容。 |
| 独立生图、生视频、生成语音 | 三类创作已有专门工作区、历史、草稿、预览和保存。媒体队列由渲染端驱动，启动时将上次的运行中记录标记为已中断。 | 每种模态都有最近会话、连续修改、版本对比及导出。媒体结果可回到原项目。上传已有画面做视觉测试保留单独入口，避免把分析结果当生成作品。视频重启后能用已有远程任务号查询；结果未知时明确说明可能已计费。 |
| 自然语音交流 | 已有系统听写和回复朗读。实时双向交流、说话打断、取消识别后的实际体验待验证。 | 说话打断时旧音频停止，新要求进入正确会话。单独的语音生成空间可试听并导出音频；两条流程分别设计操作、权限和验收。 |
| 会话和开发工作台 | 会话已有重命名、置顶、按回复分支、删除和导出。开发侧已有文件树、编辑器、终端、Git 差异与审批。README 当前首段以打开项目、测试画面和编辑代码为主。 | 聊天入口可完成第一项任务。导航菜单可发现会话管理。选中项目后按任务需要显示文件、差异和终端。对外简介和首次引导都应从用户能拿到的成品讲起。 |
| 商用与企业治理 | 当前定位为 Apple Silicon Mac 本地试用。密钥使用系统加密，会话和资料快照以本机明文保存，打包采用本地临时签名。 | 对外分发有正式签名、公证、升级及恢复演练。组织试点另外约定允许使用的模型、资料出境或出网范围、保留与删除策略，以及谁能查何种操作记录。 |

## 目标架构与取舍

保留 Electron 和现有 Agent 执行循环。优先处理一个用户任务分别散落在会话、内存队列及历史记录里造成的状态不一致。终端、编辑器和媒体画布按需呈现，读同一份任务进度与成品列表。

| 边界 | 复用的实现 | 建议的改动 |
|---|---|---|
| 桌面界面与 IPC | 首页、对话、三类媒体工作区、开发工作台、preload | 界面订阅任务事件，发送提交、补充、停止等意图。各工作区保留适合自己的布局。文本流、待审批项和成品卡读同一任务标识。 |
| 任务运行时 | agent-runtime、agent-context、run-recovery | 逐步从 main 拆出任务协调。为一次执行、一次工具调用和用户补充分别编号。收到补充就记入队列，被模型取用时另记事件。对需立即改向的任务提供停止当前生成再按新要求继续的操作，保留已完成步骤。 |
| 服务商与能力 | providers、generation、现有模型选择器 | 按「端点＋模型＋能力」保存实测结果。分别测试流式、工具调用、视觉输入、图像生成、视频提交与查询、语音合成。展示已验证、未测试、服务不支持三种状态。保留自定义端点入口。 |
| 长任务与恢复 | 会话检查点、已有视频轮询、媒体历史 | 后台负责提交、轮询、取消、恢复。保存本地任务号、远程任务号、尝试次数和输出位置。提交后响应丢失时优先按服务支持的幂等键或任务号核对。无法核对则保留「结果未知」，让用户决定是否重新付费提交。 |
| 上下文与工具权限 | 现有上下文整理、项目资料引用、只读计划和工具审批 | 整理长会话时保留当前目标、最新补充、已批准操作和成品引用。把读、写、发送外部资料和产生费用的工具分开授权。审批关联具体操作和作用范围，更改目标后重新判断尚未执行的操作是否仍适用。 |
| 成品与验证 | artifacts、草稿导出、写后回读、工作区审阅 | 为每个成品记录项目、来源任务、版本、路径、验证结果。将「写入字节一致」和「满足任务」分别展示。例如 PDF 能打开、能提取周五的日期、预算段落已删，作为这项任务的内容验收。 |
| 持久化与数据策略 | store 的原子替换、媒体 IndexedDB、系统密钥存储 | 先在规模化样本测主进程阻塞、启动与恢复时间。先抽出任务记录接口。如果整份 JSON 重写已成为瓶颈，优先迁移任务、事件和索引到 SQLite，媒体大文件存磁盘，迁移前备份并演练回退。跨提供商发送历史、工具读取项目文件均应可解释。 |

参考 Anthropic 的公开 Agent 设计，用环境反馈判断工具实际执行结果，在检查点接收用户反馈。参考 DeepSeek Harness 的上下文注入、取消及会话持久化边界。TRAE 作为开发工作区的体验参照，选取文件上下文、编辑与差异审阅。三个方向都用同一组用户任务衡量收益。公开设计可用于对照，Claude 桌面端私有实现的一致性未经验证。

## 到什么程度可以进入下一阶段

| 阶段 | 交付范围 | 通过条件（建议） |
|---|---|---|
| 1 · 文件与可控对话 | 完成首页到成品的整条路径。补充、停止和恢复有明确结果。用真实提供商建立基线。 | 选两种支持工具的真实模型，每种各跑 20 次固定任务，覆盖普通生成、中途改要求、取消和中断恢复。每种模型至少 19/20 满足各用例的预期结果。所有样本中，误报成功和未经确认的重复写入均为 0。记录文件实际内容。 |
| 2 · 多模态创作 | 图像、视频、生成语音接入同一任务与成品记录。保留独立大界面，补齐跨项目引用和真实服务验证。 | 每种模态至少验证一个真实端点的生成、预览和导出。对视频覆盖响应丢失、断网、重启、取消以及服务不支持取消的情况。支持查询的服务能找回原任务。重复提交产生的额外扣费在验证样本中为 0。实时语音对话单独验收打断和误触恢复。 |
| 3 · 专业版公测 | 安装升级、数据迁移、本地诊断、长时间运行，向试用者交付可复现的问题报告。 | 干净 Mac 完成签名包安装及升级，历史和成品可读。用大历史样本和连续运行记录故障及恢复结果。首批用户能独立完成核心任务并愿意再次使用。 |
| 4 · 企业试点 | 按买方需求确定设备部署、允许的模型、角色权限、审计、数据保留和支持安排。 | 用一个试点团队验证管理员限制能落实到真实请求，数据可导出和删除，诊断记录能定位任务问题并按权限访问。以试点反馈决定托管或私有部署。 |

**计量口径。** 本地交互延迟从按发送到界面确认计时，建议在目标 Mac 上以 P95 ≤ 150 毫秒为初始目标。服务商首字时间从请求发出到首个可显示文本计时，按模型和网络单列。文件或媒体完成时间以可打开的成品为终点。任务通过率按预期内容和实际副作用计数。首批小样本用于发现失败模式，公测再扩大样本估计稳定性。上述目标值均待真实基线校准。

## 评审依据

本轮重跑 78 项单元测试，全部通过。仓库提供七组桌面回归脚本，模型交互采用模拟服务。本轮未重跑桌面回归、调用付费模型或组织用户试用。视觉满意度、真实模型交付率、媒体账单和企业采购意愿仍需按上述方案测量。

- 品牌、共存和分发见 `README.md`、`src/brand.json` 和 `electron-builder.yml`。
- 执行与文件交付见 `src/agent-runtime.js`、`src/run-recovery.js`、`src/artifacts.js` 及 `scripts/chat-delivery-smoke.cjs`。
- 媒体恢复与语音交互见 `src/renderer-generation.js`、`src/generation.js` 和 `src/renderer-presence.js`。
- 桌面回归范围见 `package.json` 中的 `test:desktop`。仓库已有的 TRAE 工作流对照以 0.4.5 为基准，适合追溯开发工作台的设计目标。
- 公开设计参考为 Anthropic 的《Building effective agents》、DeepSeek Harness 官方仓库的《Architecture》及 TRAE 的开发工作台产品页。
